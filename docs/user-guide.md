# sanitize — руководство пользователя

Утилита для Linux, которая рекурсивно находит в веб-проекте (в первую очередь —
CMS 1С-Битрикс) файлы с персональными данными (ПДн) и секретами и **обнуляет их
(по умолчанию), удаляет, заменяет заглушками или отправляет в карантин**.

Модель угроз: на dev/тестовом стенде или перед передачей проекта подрядчикам
не должно оставаться реальных документов пользователей, выгрузок из CRM,
ключей и дампов БД. При этом сайт должен продолжать работать — служебные
каталоги CMS не затрагиваются, а обнуление вместо удаления сохраняет валидность
записей `b_file`.

## Установка

Рекомендуемый способ — `uv tool` или `pipx` (изолированное окружение,
команды попадают в `~/.local/bin`):

```bash
# через uv tool (если есть uv):
uv tool install /путь/к/sanitize --with PySide6 --with python-magic --with textual

# через pipx:
pipx install sanitize                    # только CLI
pipx install 'sanitize[gui]'             # CLI + GUI
pipx install 'sanitize[gui,magic,tui]'   # всё
```

Extras:

| Extras | Что добавляет |
|---|---|
| `gui` | графический интерфейс (PySide6 / Qt 6) |
| `magic` | определение типа файла по сигнатуре (нужна также системная `libmagic`) |
| `tui` | терминальный интерфейс для SSH (Textual) |

Из исходников (разработка): `uv sync --all-extras`, команды — `uv run sanitize …`.

Требования: Linux (Debian/Ubuntu, RHEL), Python 3.11+. Windows/macOS не
поддерживаются.

## Быстрый старт (CLI)

```bash
cd /var/www/site                 # или укажите --path

# 1. Посмотреть, что будет найдено (ничего не меняет):
sanitize --dry-run

# 2. Отчёт для аудита + секреты в скрытых файлах:
sanitize --dry-run --include-hidden --report report.json

# 3. Обнулить найденное + SQL для консистентности b_file:
sanitize --zero --yes --sql b_file.sql

# 4. (Опционально) выполнить b_file.sql на БД вручную.
```

Правило номер один: **сначала `--dry-run`, потом действие**. Dry-run
гарантированно не изменяет ни одного байта (проверяется тестами).

## Действия

| Флаг | Что происходит | Обратимость |
|---|---|---|
| `--zero` (по умолчанию) | файл обнуляется до 0 байт; владелец, права, mtime сохраняются | содержимое утрачивается, файл и запись `b_file` остаются валидными |
| `--delete` | файл удаляется; каталоги не удаляются даже если опустели | необратимо (в интерактиве требует ввода слова `DELETE`) |
| `--stub` | содержимое заменяется минимально валидной заглушкой (PDF, zip, строка текста) | необратимо, но файлы «смотрятся» нормально |
| `--quarantine DIR` | файлы упаковываются в tar.gz с `manifest.json` в каталог DIR, оригиналы удаляются | **обратимо** — см. [карантин](#карантин-и-восстановление) |

Флаги действий взаимоисключающие (`--quarantine DIR` не сочетается с
`--delete`/`--stub`). Для файлов, отслеживаемых в `b_file` (каталоги под
`upload/`), после `--zero` сгенерируйте `--sql b_file.sql` и выполните его
на БД: `UPDATE b_file SET FILE_SIZE = 0 …` — идемпотентно.

**Конфиги с секретами** (`bitrix/.settings.php`, `bitrix/php_interface/dbconn.php`,
`.env`, `.htpasswd`, `.my.cnf`, `.pgpass`, `.netrc`) **никогда не изменяются** —
они попадают только в отчёт (категория «только отчёт»), а утилита завершается
с кодом 2.

## Справочник CLI

```
sanitize [--path DIR] [--dry-run]
         [--zero | --delete | --stub | --quarantine DIR]
         [--preset bitrix|generic] [--category ID,...] [--ext .x,.y]
         [--exclude GLOB]... [--include-hidden] [--follow-symlinks] [--no-one-filesystem]
         [--min-size SIZE] [--older-than DURATION]
         [--magic] [--deep-scan] [--threads N] [--no-hash]
         [--report FILE.json] [--sql FILE] [--json] [--yes] [--quiet] [--verbose]
         [--gui] [--tui] [--version]
sanitize restore ARCHIVE [--dry-run]
```

| Флаг | Назначение |
|---|---|
| `--path DIR` | корень проекта (по умолчанию — текущий каталог); системные корни (`/`, `/home`, `/usr`, `/etc`, `/var`…) запрещены |
| `--dry-run` | только список и сводка, никаких изменений |
| `--preset` | `bitrix` (исключения служебных каталогов, рискованные каталоги) или `generic` (универсальный) |
| `--category` | только перечисленные категории: `docs,sheets,slides,archives,keys,backups,mail,media,logs,secrets_report` |
| `--ext` | дополнительные расширения, например `--ext .foo,.bar` |
| `--exclude` | glob-исключение (можно повторять): `--exclude 'upload/private/**'` |
| `--include-hidden` | учитывать скрытые файлы (`.env` и другие точечные) |
| `--follow-symlinks` | заходить в каталоги-симлинки (по умолчанию нет) |
| `--no-one-filesystem` | разрешить переход на другие файловые системы |
| `--min-size` | только файлы больше: `1024`, `10M`, `2G` |
| `--older-than` | только файлы старше: `30d`, `12h`, `90m`, `7w` |
| `--magic` | определять тип по сигнатуре для файлов без расширения |
| `--deep-scan` | искать ПДн в содержимом (email, телефон, паспорт, СНИЛС, ИНН, карта) |
| `--threads N` | параллельный обход (по подкаталогам первого уровня) |
| `--no-hash` | не считать sha256 перед изменением (быстрее на больших файлах) |
| `--report` | файл отчёта; формат по расширению: `.json` или `.md` |
| `--sql` | SQL-скрипт `b_file` (`FILE_SIZE = 0`) для обнулённых файлов под `upload/` |
| `--json` | машиночитаемый вывод в stdout |
| `--yes` / `-y` | без интерактивных подтверждений (для CI) |
| `--quiet` / `-q` | минимум вывода |
| `--verbose` / `-v` | подробный журнал |

## Exit-коды

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | часть файлов не обработана (нет доступа) |
| 2 | найдены конфиги с секретами (`report_only`) — удобно для CI/hook |
| 3 | отказ: небезопасный путь, нет подтверждения, неверные аргументы |
| 130 | прервано пользователем (Ctrl+C) |

## GUI

Запуск: `sanitize-gui` или `sanitize --gui` (нужен extras `gui`).
GUI под root не запускается и не рекомендуется — для чужих прав используйте CLI.

Единственное окно, четыре блока сверху вниз.

### Параметры поиска

Поле **Путь** (с кнопкой «Обзор…», `Ctrl+F` — фокус, `Enter` — запустить
поиск), радио профиля **Битрикс / Общий**, чекбоксы категорий и флагов.
У каждого чекбокса — кнопка **«?»**: клик открывает подробное пояснение
(закрытие — повторный клик, клик вне или Esc; при наведении показывается
краткий тултип).

| Параметр | Суть |
|---|---|
| Документы | PDF/Word/сканы — договоры, резюме; `.txt`/`.md` только под `upload/` |
| Таблицы/экспорт | xls/csv/xml/json — реестры и выгрузки 1С/CRM, высокий риск |
| Презентации | pptx/odp — внутренние материалы |
| Архивы | zip/rar/tar.gz — копии документов и дампов |
| Подписи/ключи | pem/p12/id_rsa — компрометация ключа = компрометация сервера |
| Бэкапы/дампы | sql/bak + всё содержимое `bitrix/backup/` |
| Почта/контакты | eml/vcf — переписка и контакты |
| Аудио/видео | записи звонков/встреч; **выключено по умолчанию** |
| Логи и кэш | log/tmp + `bitrix/cache`, `upload/tmp`, `bitrix/html_pages` |
| Исключить служебные каталоги Битрикс | не заходить в код и ресурсы CMS — иначе сайт сломается |
| Проверять по сигнатуре | тип по содержимому для файлов без расширения |
| Глубокий поиск ПДн | регексы ПДн по содержимому (замедляет скан) |
| Следовать по симлинкам | риск выхода за корень; по умолчанию выключено |
| Скрытые файлы | `.env`, `.htpasswd` и другие секреты; по умолчанию выключено |

### Прогресс

Фаза 1 — «Подсчёт каталогов…» (неопределённый прогресс), фаза 2 — процент
по числу файлов и текущий путь. Кнопка **«Стоп»** (`Esc`) мягко прерывает
сканирование или действие.

### Результаты

Дерево трёх уровней: **категория → группа → файл**.

- Категория показывает счётчик, суммарный размер и метку риска
  («⚠️ высокий риск», «— только отчёт»).
- **Свёртывание**: категория развёрнута по умолчанию, если в ней ≤ 10 файлов;
  при большем количестве — свёрнута.
- **Группировка** (селектор справа от фильтра): «Нет / По каталогам /
  По расширениям». Если в категории больше 20 файлов, они автоматически
  собираются в группы (например `upload/user_documents (83, 251 МиБ)`) —
  каждая группа со своим tri-state чекбоксом. Режим запоминается между
  запусками.
- **Чекбоксы** (tri-state): снять категорию — снимутся все группы и файлы
  внутри; снять группу — её файлы. Категория «Конфиги с секретами» показывается,
  но не выбираема — она всегда только в отчёте.
- **Фильтр** — подстрока по путям (рекурсивно по дереву).
- Колонка «Файл» вчетверо шире остальных.
- Контекстное меню файла: «Открыть каталог», «Копировать путь»,
  «Исключить каталог из поиска» (добавляет glob на текущую сессию).

### Действие

Радио «Обнулить / Удалить / Карантин → …» (для карантина — каталог **вне**
корня проекта). «Выполнить для выбранных» активна, когда есть выбранные
файлы. Диалог подтверждения показывает действие, число файлов и объём;
для удаления требует ввести `DELETE`. После выполнения обработанные файлы
помечаются серым/зачёркнуто (не исчезают), появляется сводка с кнопкой
«Открыть отчёт…» (автоотчёт `sanitize-report.json` рядом с текущим каталогом).
При ошибках доступа предлагается команда с `sudo` для копирования.

Настройки (путь, чекбоксы, режим группировки, геометрия) сохраняются в
`~/.config/sanitize/`.

## TUI

Запуск: `sanitize --tui` (extras `tui`). Минимум для headless-стендов по SSH:
путь, чекбоксы категорий, таблица найденного, кнопки «Сканировать»,
«Обнулить», «Удалить» (с подтверждением и вводом `DELETE`). Действие
применяется ко всем найденным файлам выбранных категорий — для точечной
работы используйте CLI/GUI. Клавиши: `s` — сканировать, `x` — стоп,
`q` — выход.

## Профили и категории

| id | Категория | Расширения / имена | Риск |
|---|---|---|---|
| docs | Документы | pdf, doc(x), rtf, odt, epub, djvu…; txt/md — только `upload/` | средний |
| sheets | Таблицы/экспорт | xls(x), csv, tsv, ods; xml/json/yaml — только `upload/` | высокий |
| slides | Презентации | ppt(x), pps, odp | средний |
| archives | Архивы | zip, rar, 7z, tar.gz, iso, dmg… | высокий |
| keys | Подписи/ключи | sig, pem, key, p12, kdbx…; имена id_rsa и др. | высокий |
| backups | Бэкапы/дампы | sql, bak, dump, sqlite…; всё содержимое `bitrix/backup/` | высокий |
| mail | Почта/контакты | eml, msg, pst, vcf, ics | высокий |
| media | Аудио/видео | mp3, mp4, mkv… (выкл. по умолчанию) | низкий |
| logs | Логи и кэш | log, tmp, swp; каталоги `bitrix/tmp`, `bitrix/cache`… | средний |
| secrets_report | Конфиги с секретами | `bitrix/.settings.php`, `dbconn.php`, `.env`, `.htpasswd`… | высокий, только отчёт |

Профиль `generic` — те же категории без Битрикс-специфики (без `only_under`,
без исключений `bitrix/*`). Изображения намеренно не включены. Обоснования —
`docs/bitrix-notes.md`.

## .sanitizeignore

Положите файл в корень проекта — пути из него исключаются из поиска
(подмножество gitignore: комментарии `#`, `каталог/`, якорные `/путь`,
`**`, `*`, `?`; отрицания `!` не поддерживаются):

```gitignore
# комментарий
upload/old_forms/
*.log
/public_docs/**
```

## Отчёты

- `--report report.json` — полная машина читаемая версия: метаданные запуска,
  сводка по категориям, каждый файл (путь, размер, категория, рискованные
  каталоги, счётчики ПДн), действия с sha256 и владельцем/правами, пропуски.
- `--report report.md` — человекочитаемый Markdown.
- GUI автоматически пишет `sanitize-report.json` после выполнения действия;
  полный отчёт — кнопка «Сохранить отчёт…».
- `--sql b_file.sql` — скрипт `UPDATE b_file SET FILE_SIZE = 0 …` только для
  реально обнулённых файлов под `upload/` (идемпотентный). Сверить скрипт
  с дампом БД (без подключения к БД) можно так:

  ```bash
  python scripts/check_b_file_sql.py dump.sql b_file.sql
  ```

  Файлы, не зарегистрированные в `b_file` (кастомные модули часто пишут на
  диск напрямую), дают безопасный no-op UPDATE.

## Карантин и восстановление

```bash
# упаковка (каталог должен быть вне корня проекта):
sanitize --path /var/www/site --quarantine /var/quarantine --yes

# что внутри будет восстановлено:
sanitize restore /var/quarantine/sanitize-quarantine-20261106-120000-….tar.gz --dry-run

# восстановление (существующие файлы не перезаписываются):
sanitize restore /var/quarantine/sanitize-quarantine-20261106-120000-….tar.gz
```

В архиве лежит `manifest.json`: исходный путь, размер, sha256, uid/gid/mode,
mtime, категория. Восстановление возвращает содержимое, права и mtime;
владелец — best-effort (без root пропускается).

## Гарантии безопасности

- `--dry-run` не изменяет ни одного байта (автотест по хэшу дерева).
- Без TTY и без `--yes` действия не выполняются (код 3).
- `--delete` в интерактиве требует ввода `DELETE`.
- Секретные конфиги никогда не изменяются — защита в CLI, GUI и ядре.
- Симлинки не обходятся и не изменяются (без `--follow-symlinks`).
- Скрытые файлы не сканируются без `--include-hidden`.
- Идемпотентность: повторный запуск ничего не меняет
  (`skipped_empty`/`already_absent`).
- Владелец/права/mtime сохраняются при zero/stub.
- `.git`-предупреждение: чистка файлов не убирает их из истории Git.

## FAQ

**`zsh: command not found: sanitize`**
Утилита установлена в окружение инструмента/venv. Установите глобально
(`uv tool install` / `pipx install`) и выполните `rehash` (zsh) или откройте
новый терминал. Проверка: `sanitize --version`.

**GUI не открывается по SSH / ошибка Qt platform**
GUI нужен дисплей: `ssh -X`, либо терминальный `sanitize --tui`. Если на
десктопе ошибка `xcb`/`wayland` — установите `qt6-wayland` или задайте
`QT_QPA_PLATFORM=xcb`.

**`--magic` не работает**
Нужны extras `magic` и системная библиотека libmagic
(Debian/Ubuntu: `apt install libmagic1`). Без них утилита работает,
просто пропускает сигнатуры.

**«Пропущено: N (нет доступа)»**
Часть каталогов/файлов недоступна текущему пользователю. В отчёте раздел
«Пропущено»; для полной обработки: `sudo sanitize --path … --report …` (CLI).

**Файлы в отчёте есть, а в `b_file` их нет**
Нормально: кастомные модули часто пишут файлы под `upload/` напрямую, без
учёта в БД. Такие UPDATE безопасно промахнутся; сверить можно
`scripts/check_b_file_sql.py`.

**Повторный запуск снова показывает те же файлы**
Файлы обнулены, но существуют — классификация идёт по имени/расширению.
Действия над ними — no-op (`skipped_empty`); в отчёте `actions_ok` без
реальных изменений. Скрыть пустые из выдачи: `--min-size 1`.

**Карантин/восстановление**
Каталог карантина обязан быть вне корня проекта. `restore` не перезаписывает
существующие файлы — удалите/переименуйте конфликт, если нужна именно
версия из архива.
